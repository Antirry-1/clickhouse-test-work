# HUMAN_CHECK.md — простая проверка проекта

Этот файл написан простым языком для человека, который **не разбирается** в технических
деталях. Делай по шагам сверху вниз. Если все галочки стоят — проект работает.

> Нужен только **Docker**. Всё остальное запускается само внутри контейнеров.

---

## 1. Что должно получиться

- Поднимаются два сервиса:
  - **ClickHouse** — база данных, где лежит 1 миллион SMS.
  - **Apache Superset** — веб-приложение с дашбордом (графиками).
- Superset открывается в браузере по адресу **http://localhost:8088** (логин `admin`, пароль `admin`).
- В Superset есть дашборд **SMS Operations** с графиками и фильтрами слева.
- Успешный результат выглядит как картинка [`screenshots/sms_operations_dashboard.png`](../screenshots/sms_operations_dashboard.png):
  слева фильтры **Customer** и **Sent date**, справа большие числа (Delivery rate ≈ **80%**,
  Revenue ≈ **99.5k**) и графики (по дням, топ стран, топ операторов, по валютам, статусы).

## 2. Самая короткая проверка

Открой терминал в папке проекта и выполни **по очереди**:

```bash
# 1) Запустить всё одной командой (первый раз — несколько минут: качаются образы и грузится 1 млн строк)
docker compose up -d --build

# 2) Подождать и проверить, что всё поднялось и данные на месте
make smoke-test
```

В конце `make smoke-test` должно быть написано: **`✅ SMOKE TEST PASSED`**.

- **Сколько строк в базе** (должно быть `1000000`):
  ```bash
  make rows
  ```
- **Где дашборд:** открой в браузере http://localhost:8088 → логин `admin` / `admin` →
  меню **Dashboards** → **SMS Operations**.
  (Прямая ссылка: http://localhost:8088/superset/dashboard/sms_operations/)
- **Какой скриншот открыть:** `screenshots/sms_operations_dashboard.png` — так дашборд должен выглядеть.

## 5. Красные флаги (что-то не так)

Если видишь это — проект **не** готов к показу:

- ❌ `make rows` показывает **не** ~1 000 000 (например, 0). → Данные не сгенерировались. Запусти `make generate`.
- ❌ http://localhost:8088 **не открывается**. → Superset не поднялся. Смотри `docker compose logs superset`.
- ❌ На дашборде **нет фильтров** слева. → Дашборд собран неверно. Запусти `make dashboard`.
- ❌ Дашборд **пустой** (графики без данных). → Проверь `make rows`; если 0 — `make generate`, потом `make dashboard`.
- ❌ В графиках видны удалённые записи — soft-delete **не исключён**. → Дашборд должен читать
  `messages_mart_active` (вью без `deleted_at`). Это уже настроено; если нет — см. DESIGN.md №6.
- ❌ Нет объяснения ключей ClickHouse. → Они есть в **DESIGN.md** (разделы 2–5). Покажи их.

## 6. Простые команды диагностики

Скопируй и выполни — это безопасно (ничего не ломает, только показывает):

```bash
# Статус контейнеров
docker compose ps

# Логи (если что-то не поднялось) — Ctrl+C чтобы выйти
docker compose logs --tail=100
docker compose logs superset      # только Superset
docker compose logs clickhouse    # только ClickHouse

# Сколько строк в таблице (ожидаем 1000000)
make rows

# За какой период данные (ожидаем 2025-01-01 .. 2025-12-31)
make period

# Доля доставленных SMS (ожидаем ~80%)
make delivery-rate
```

Если совсем всё запуталось — полный сброс и пересборка с нуля:
```bash
make clean    # удаляет контейнеры и данные
make up       # поднимает заново
make smoke-test
```
